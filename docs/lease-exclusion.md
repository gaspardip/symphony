# Local lease mutation exclusion

`LeaseManager.acquire/4`, `refresh/3`, and `release/2` serialize their read/decision/write sequences through an atomic `mkdir` of `<lease path>.lock`. This works across independent BEAM processes that share the same local filesystem store. Each call waits at most approximately one second for an occupied critical section before returning `{:error, {:lease_lock_timeout, lock_path}}`; filesystem setup failures return `{:error, {:lease_lock_failed, lock_path, reason}}`. Callers must not treat these results as acquired or released ownership.

The call which creates the directory removes it when its operation returns or raises. It never removes another call's existing directory, never uses the lease TTL to steal a lock, and never automatically clears an orphan. If a process is killed during this critical section, the remaining directory deliberately prevents further mutation. Diagnosis identifies its path; recovery requires inspection and an explicit operational decision after confirming the holder is no longer active. This is a fail-closed interruption outcome, not automatic crash recovery. Failure to release a created lock raises an explicit filesystem error.

Existing lease TTL, epoch increments, owner comparison, timestamp normalization and explicit force-release API semantics remain unchanged. Valid JSON which is not an object is rejected by `read/1` as `:invalid_lease`, so it cannot accidentally flow into ownership mutation. Existing handling of malformed timestamps and ownerless force release is legacy behavior and is not claimed as strict corruption validation in this change.

The critical-section lock protects metadata decisions only. It does not stop a worker which has lost ownership, fence external side effects, or provide exactly-once execution across hosts. All mutating participants must run the same locking protocol and use the same store; old binaries, direct file writers and network filesystems are outside the tested guarantee. A higher-level caller may still explicitly force release a lease using `release(issue_id)`; this patch does not change that policy decision.

`elixir/test/symphony_elixir/lease_concurrency_test.exs` exercises simultaneous acquire in three clean rounds, release versus takeover, and refresh versus takeover using distinct OS/BEAM processes behind a shared start barrier. It also verifies that a foreign/orphaned lock remains untouched, setup errors block mutation, and invalid JSON/non-map payloads are preserved. The old lease tests remain unchanged. Test results must be recorded from the actual source cut; writing these tests alone does not establish PB-04/CR-09 acceptance or a video.
